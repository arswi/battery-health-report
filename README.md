# 电池健康报告（Android APK · v4.5.2）

导入手机生成的 bugreport，把系统自己测出来的电池容量算成健康度，按机型分开统计，串成衰减曲线。

包名 `com.xiaolei.battery`，minSdk 26（Android 8+），targetSdk 34，约 700 KB，零第三方依赖。

## 安装

1. 把 `电池健康报告.apk` 传到手机，点开安装（允许"未知来源"）
2. 拨号盘输入 `*#*#284#*#*` 生成 bugreport（1~2 分钟）
3. 文件在「文件管理 → 手机」的 `Download` / `MIUI/debug_log`，名字类似 `bugreport-2026-10-21-182853.zip`
4. 点右上角「导入」选中它；或在文件管理里直接点这个 zip，选「电池健康报告」打开

不需要任何后台权限、自启动或省电放行。

## 界面结构

```
顶栏     电池健康报告 …… [导入] [?帮助]
机型栏   小米 13 (12)   小米 15 (3)   ……   ← 每台机器一个 chip，点它切换
内容区  ┌ 底部菜单 ─────────────────┐
        │ 概览：机型头卡 + 六宫格基础信息 + 每日自动任务 │
        │ 详细：健康度环形 + 变化曲线（含官方寿命参考）+ 全部报告列表 │
        │ 设置：主题（跟随系统/深色/纯黑/白天）+ 使用声明 + 版本信息 │
```

- **概览**（简洁模式）：OS 版本 / 机型名 / 报告生成时间 / 设计容量徽标，
  六宫格 = 满充容量、充电循环、估算满充容量、上次学习容量、最小学习容量、最大学习容量
  （每项都标出相对设计容量的百分比），底部是设计容量校准 / 导出 CSV / 清空。
- **详细**：健康度环形图 + 变化曲线 + 按时间倒序的报告列表（点卡片看该份报告的全部数据）。
- **机型隔离**：记录按 `ro.product.model` 分组存储（联合主键 device_key + report_ts），
  曲线、列表、统计、设计容量校准全部只作用于当前选中的机型，绝不和其它机型混算。

## 主题

设置页四选一：**跟随系统**（系统深色模式开=深色、关=白天）/ **深色**（原深蓝灰）/
**纯黑**（AMOLED，背景 #000000）/ **白天**（浅色）。
状态栏/导航栏颜色跟随主题，选择会被记住；跟随系统在系统切日夜时自动换肤。

## 曲线配色（详细页）

不做拟合、不给预测，报告点直接连线；线的颜色由**整体健康度变化**决定：

| 变化 | 颜色 |
|---|---|
| 变化 < 1%（含持平/上升） | 绿 |
| 下降 1% ~ 5% | 橙 |
| 下降 > 5% | 红 |

80% 虚线更换参考线保留。

## 数据与时间

- 每条记录的横轴是**报告自身的生成时间**：优先取报告正文的 `== dumpstate: yyyy-MM-dd HH:mm:ss` 行，
  取不到再依次回退到内层报告文件名 → 外层文件名 → 导入时刻；导入完成后会在状态栏注明时间来源。
- 同一份报告重复导入只更新不重复计点。
- 容量来源优先级：`POWER_SUPPLY_CHARGE_FULL` → `Last/Min/Max learned battery capacity` →
  `Estimated battery capacity`；设计容量：手动校准 → 内置机型库官方典型标称 →
  固件电源档案 → `POWER_SUPPLY_CHARGE_FULL_DESIGN`（固件值常是"额定值"口径或动态估算，
  与官方标称有出入时以备注对照，>8% 标注"疑似动态估算"）。
- 单位自适应：µAh / mAh / Ah（小米 13 的 `4` Ah 会还原成 4000 mAh）。
- 设计容量校准按机型分别保存（换第三方电池、官方值与机器不符时用），可随时清除。

## 崩溃可查

全局崩溃捕获写 `filesDir/crash.txt`，顶栏下方出现红色提示条，点开可查看/复制/清除。
